# Product storytelling — dirección previa al diseño

Dos homepages estáticas independientes. No importan componentes corporativos, GSAP ni servicios de contacto. No publicables: noindex. Español con marcadores Angular i18n.

## Sistema compartido

Graphite #11191B, offwhite #F2F4F1, mint #97E5B3, slate #65787C. Neutrales derivados para interfaces. Geist Sans para contenido; Geist Mono para códigos y cantidades. Titulares 76/52 desktop, 40/32 móvil. Texto principal 18/16; datos principales de UI móvil 12 px y anotaciones secundarias menores en los mockups. Retícula máxima 1280 px, márgenes adaptables.

## A — Tu operación, a la vista

Hero oscuro, título y beneficio en dos columnas, gran aplicación clara a lo ancho. El panel deja visible pedido, cliente, artículos y estado. Servicios con un escaparate amplio y dos escenas complementarias. El contraste da protagonismo al producto. Cierre claro y directo.

```
ALANT                                   servicios / contacto
Software a medida.         beneficio y CTA
Tu operación, a la vista.
[ sidebar | pedidos + detalle del pedido                  ]
[ software a medida — operación / pantalla               ]
[ integración: pedido → ERP ][ IA: documento / revisión  ]
[ proceso breve ] [ cierre / contacto ] [ footer          ]
```

## B — Del pedido al trabajo resuelto

Hero claro asimétrico: titular a izquierda, composición de orden de compra y registro de pedido a derecha. Servicios en tres capítulos alternados con superficies claras y oscuras; las mismas referencias de pedido permiten seguir la historia. Se explica una operación, no una arquitectura abstracta.

```
ALANT                                   servicios / contacto
Construimos el software    [ orden de compra             ]
que tu empresa necesita.          [ registro operativo   ]
[ 01 / Software       | panel de preparación de pedido   ]
[ ERP / pedido        | 02 / Integraciones                ]
[ 03 / IA             | documento y revisión             ]
[ proceso editorial ] [ cierre mint ] [ footer            ]
```

## Datos y límites

Ejemplo conceptual de una distribuidora. Pedido #1048 / orden OC-048 / registro ERP PV-1048. Cliente de ejemplo. 24 cajas apilables CJ-24 a ARS 8.500 = 204.000; 12 kits de etiquetas ET-12 a ARS 2.500 = 30.000; total neto ARS 234.000. Fecha «viernes» ambigua, revisión humana pendiente. No métricas de impacto, clientes ni proyectos reales. Mockups estáticos sin controles engañosos: el chrome de software es ilustrativo y cada figura tiene descripción accesible.

- https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md — composición deliberada, contenido específico, crítica mediante capturas. La identidad aprobada prevalece sobre preferencias genéricas.
- https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md y references/quick-reference.md — estudiadas directamente; sin instalar ni ejecutar el buscador local. Aplicamos sus criterios de contraste, jerarquía, foco, responsive y lectura.
- https://linear.app/ — inspección visual de hero y sección Intake: escala del producto, titular + pantalla, contexto de una acción.
- https://attio.com/ — inspección visual de hero y Build pipeline: tabla contextual + detalle superpuesto, beneficio corto.
- https://n8n.io/ — inspección visual de hero y caso de onboarding: relato a partir de una tarea reconocible. Algunos vídeos no reproducibles en el navegador; no se evaluó su motion.

No se reutilizan capturas, logos ni assets de estas marcas. No se implementa movimiento. La animación futura se describe después de revisar los diseños estáticos.
